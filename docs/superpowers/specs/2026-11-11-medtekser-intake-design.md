# MedTekser: нақты өтінім қабылдау

**Күйі:** мақұлдауға ұсынылатын дизайн

## Мақсат

Компания сайтта жіберген өтінім операторға сервер арқылы жетіп, тұрақты сақталуы керек. Қазір жарияланған GitHub Pages нұсқасы `github.io` доменінде жергілікті демо API-ды қосады: өтінім тек сол келушінің браузеріндегі `localStorage`-ке жазылады. Серверге сұрау жоқ, сондықтан оператор өтінімді көрмейді. ЖСН тексергіші де жергілікті үлгі деректерін қарап, ресми тізілім сияқты нәтиже көрсетеді.

Бұл өзгеріс өтінім қабылдауды шынайы етеді және демо әрекеттерін нақты қызмет ретінде көрсетпеуге бағытталады.

## Мақсатты пайдаланушылар

- Шымкент пен Түркістан облысындағы қызметкерлерін медтексеруге жіберетін компаниялардың HR мамандары.
- Жаңа өтінімдерді қабылдап, өңдейтін MedTekser операторы.

## Мақсаттар

- Нақты сайттан келген өтінім Python API арқылы ортақ SQLite дерекқорына сақталсын.
- Сәтті хабарлама тек сервер өтінімді қабылдаған соң көрсетілсін.
- API бапталмаған не қолжетімсіз болса, өтінім сәтті жіберілді деп көрсетілмей, WhatsApp арқылы байланысу жолы ұсынылсын.
- Демо ЖСН тексергіші нақты тізілімнің растауы сияқты көрінбесін; нақты интеграция жоқ кезде ресми тексеру мен заңдық қорытындыны уәде етпесін.
- Өндірістік серверде әлсіз әдепкі әкімші құпиясөзі және демо тапсырыстар қолданылмасын.
- Қазіргі GitHub Pages адресін сақтау.

## Жұмысқа кірмейтін ауқым

- Мемлекеттік немесе медициналық тізіліммен шынайы интеграция жасау.
- Медициналық қызметтің лицензиясын, тарифін, серіктес клиникасын немесе заңға сәйкестігін растау.
- Қызметкерлердің ЖСН-і немесе медициналық деректерін жаңа түрде жинау.
- Хостингке жариялау, домен ауыстыру, құпиясөз/токен енгізу немесе Telegram хабарламаларын қосу.
- HR кабинетінің жалпы дизайнын қайта жасау.

## Қарастырылған тәсілдер

1. **GitHub Pages беті + бөлек Python API (ұсыныс).** Қазіргі сайт адресі қалады. Фронтенд нақты API мекенжайын конфигурациядан алады; сервер тек `https://dansho09.github.io` шыққан сұрауларға CORS рұқсатын береді; SQLite дерегі тұрақты томда сақталады. Артықшылығы — бар URL мен backend-ті сақтайды. Айырбасы — API-ға жеке хостинг керек және нақты API домені шыққанша форма өндірістік түрде іске қосылмайды.
2. **Сайт пен API-ды бір Docker хостқа көшіру.** Қолданыстағы Python сервері статикалық беттер мен API-ды бірге береді, сондықтан CORS қажет емес. Орнатуы қарапайым, бірақ жаңа жариялау адресі немесе доменді ауыстыру қажет болады.
3. **Сыртқы форма қызметін қосу.** Өтінімді сыртқы провайдер сақтай алады. Іске қосуы жылдам, бірақ бар админ панелі және SQLite серверімен бөлек интеграция керек болады.

**Ұсынылатын таңдау:** бірінші тәсіл. Пайдаланушы нақты өтінім қабылдау жолын таңдады; қазіргі сайт адресін сақтау — өзгерісі аз нұсқа. Хостинг провайдері мен API домені бұл құжатта таңдалмайды; backend-ті орналастырмас бұрын сол деректер қажет.

## Шешімнің қысқаша сипаттамасы

### Фронтенд

- `static/common.js` API base URL-ды бір нақты конфигурациядан оқиды.
- Browser-local preview API тек `localhost` және әзірлеушінің локалдық preview режимінде жұмыс істейді; үлгі жазбалары жасалмайды.
- GitHub Pages-та API мекенжайы жоқ болса, форма өтінімді «жібердім» деп көрсетпейді; байланысқа шығу үшін WhatsApp-ты ұсынады.
- API `201` және өтінім нөмірін қайтарғанда ғана сәтті экран көрсетіледі. Қате болғанда енгізілген мәндер сақталып, қайта көруге болады.
- ЖСН іздеу компоненті алынып тасталады. Оның орнына сайт тізілімге қосылмағанын және ашық бетке ЖСН не денсаулық деректерін енгізбеу керегін анық көрсетеді.

### API және сақтау

- Қолданыстағы `server.py`-дегі `/api/requests` және SQLite схемасы пайдаланылады.
- Frontend origin allowlist-і дәл ағымдағы GitHub Pages origin-імен шектеледі; `OPTIONS` preflight және JSON / `Authorization` тақырыптары өңделеді. Cookie арқылы аутентификация қоспаймыз.
- Өндірістік SQLite файлы тұрақты томдағы `DB_PATH` арқылы сақталады.
- Өндірісте `ADMIN_PASSWORD` міндетті болады; бос немесе әдепкі `admin123` болса, сервер іске қосылмайды.
- Ешбір ортада базаға демо жазба автоматты енгізілмейді. Жергілікті preview бос дерекқордан басталады.
- Ашық өтінім endpoint-і үшін серверде уақытша жадыдағы IP rate limit қолданылады; IP дерегі SQLite-ке жазылмайды. CAPTCHA қоспаймыз.
- Telegram хабарламасын қоспаймыз. Жеке деректерді үшінші тарапқа жіберетін хабарлама нақты келісімсіз бапталмайды.

### Дербес деректер және хабарлама

Қазіргі формадағы өрістер (компания, БСН, байланыс тұлға, телефон, email, жоспарланған күн, пікір, қызметкерлер саны және тексеру түрі) өзгеріссіз қалады. Жаңа медициналық ақпарат пен қызметкердің ЖСН-ін жинамаймыз. Сервер API-ін жарияламас бұрын, пайдаланушы бекіткен дербес деректер туралы хабарлама/құпиялық құжаты және деректердің қайда сақталатыны қажет. Құжатсыз жаңа заңдық уәде қоспаймыз.

## Шектеулер мен болжамдар

- GitHub Pages Python серверін іске қоса алмайды; нақты өтінімдер үшін бөлек Python API хосты қажет.
- Репозиторийде `server.py`, `Dockerfile`, SQLite және әкімші панелі бар. GitHub Pages-тағы `/api/config` қазір 404 қайтарады.
- Жоба бастапқы RU/KZ екі тілінде қалады.
- Пайдаланушы жариялауды сұрамағандықтан, жұмыс код пен орналастыруға дайын конфигурациямен шектеледі. Жарияламас бұрын API хосты, API URL, құпиясөз, тұрақты диск және құпиялық хабарламасы қажет.
- Лицензия, клиника, тариф, күту уақыты және заңға сәйкестік туралы қазіргі мәтінге иесінен дәлел алынбады; оларды расталған дерек ретінде жарнамаламаймыз.

## Сәттілік өлшемдері

- Бапталған API-ға жіберілген нақты өтінім SQLite-ке бір рет сақталып, әкімші панелінде көрінеді.
- API жоқ/404 не CORS қатесі болса, «сәтті жіберілді» экраны көрсетілмейді; формадағы деректер жоғалмайды.
- Басқа origin-нен API сұрауы CORS арқылы қабылданбайды.
- Жиі жіберілген өтінімдер шектеліп, сервер `429` қайтарады; артық жазба дерекқорға түспейді.
- Өндірістік іске қосу әлсіз әдепкі әкімші құпиясөзін қабылдамайды және демо тапсырыс/қызметкер жазбаларын жасамайды.
- Жария беттегі демо тексергіш нақты ЖСН бойынша ресми мәртебе не заңдық қорытынды бермейді.

## Кейін нақтылау қажет

- API-ды қай Docker хостында іске қосамыз және оның ашық HTTPS мекенжайы қандай?
- Деректердің сақтау орны мен клиентке көрсетілетін құпиялылық/келісім мәтінін кім бекітеді?
- Нақты серіктес клиникалар, лицензия және бағалар туралы жарияланатын ақпаратты кім растайды?

Бұл жауаптар жергілікті кодты әзірлеуге қажет емес; олар API-ды баптап, сайтты көпшілікке ұсынбас бұрын қажет.

## Қауіпсіздік бойынша келесі күшейту

Пайдаланушының «барынша күшейту» өтініші бойынша, бұрынғы GitHub Pages + Python API архитектурасын сақтап, қосымша мына өзгерістер жасалады:

- Жаңа компания кабинетінің кіру коды кемінде 64 бит кездейсоқ энтропиямен жасалады; бұрыннан жасалған кодтар өтпелі кезеңде әлі де тексеріледі.
- Компания және әкімші кіру endpoint-терінде бір IP-ден 15 минутта 10 әрекеттен артық жіберуге болмайды. IP тек қысқа мерзім жадыда сақталады.
- Админ сессиясы 12 сағат, компания сессиясы 14 күн жарамды.
- Әдепкі админ құпиясөзі кодтан және мысал конфигурациясынан алынады; құпиясөз жоқ кезде серверлік админ кіруі өшіріледі. Жергілікті браузер preview-і ашық интернетте қолданылмайды.
- Беттер iframe ішіне салынбайды; рұқсат тақырыптары камера/микрофон/геолокацияны шектейді; production HTTPS жауабында HSTS беріледі.
- Кіру мен өтінім қателері экран оқу құралдарына жарияланады.
- LocalStorage preview көрініп белгіленеді, оның кіруі сервермен расталмайтыны және нақты өтінім жібермейтіні айтылады; жеке/медициналық деректерді енгізбеу ескертіліп, жалған прогресс пайызы алынады.
- Қызметкер деректері CSV-ге экспортталғанда Excel formula injection-нан қорғалады.
